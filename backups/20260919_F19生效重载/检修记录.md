# OpenIME 深度检修记录

日期：2026-09-12  
范围：全量源码审阅 + 真机 UDL 对照 + 预期逻辑回归

## 必须知道的结论

### 1. 真机文件头不能清零（严重）
真机 `ChsPinyinUDL.dat` 头 0x2400 中，**0x470 起有大量索引/统计数据**。
旧版 `write()` 每次新建全零头再写词条，会抹掉这些区域（约 299 字节差异）。

**修复**：`UdlFile.read()` 保存 `raw_header`；`write(..., preserve_header=True)`
默认复制原头，只更新 count@0xC 与 timestamp@0x14。合并/删除/替换均走此路径。

### 2. 拼音索引表必须与真机对齐
`pinyin_table.json` 已用真机 8242 条投票重建；idx0=`a`。对真机校验约 98.6%
（剩余为多音字默认读音差异）。禁止改回未校准表。

### 3. 简拼写入
默认 `jianpin=b'\x00\x00\x00'` 必须重新计算，不能当成已写好。

### 4. 空拼音哨兵
空拼音写 `0xFFFF`，不能写 0（0=音节 a）。

# 第五轮追加功能（2026-09-18）：多选 / 分区 / 分区清除

需求：浏览词库支持多选（Shift 连选）、词条分区、按分区清除；分区依托
`%APPDATA%\OpenIME` 自带 config，整目录拷贝即可暴力移植到其他机器，
原机器自动记录的导入批次在目标机单独成区。

## 设计

- **手动分区**存 `%APPDATA%\OpenIME\partitions.json`
  （`{"format":"openime-partitions","version":1,"partitions":{name:{created,machine,words}}}`），
  写盘走临时文件 + `os.replace` 原子替换；读盘缺文件视为空，**文件存在但解析失败必须抛错拒写**
  （初版"坏 JSON 容错为空"会在下次保存时覆掉全部既有分区，已在子 agent 查错轮改为严格模式，见下）。
- **自动分区**不落新数据：从 `%APPDATA%\OpenIME\history\` 导入 manifest 派生，
  命名 `[自动] {machine} {time} {source首行[:24]}`。`_record_history` 新增
  `machine: platform.node()` 字段；旧记录无该字段归入"旧记录"。
  因此拷贝 OpenIME 配置目录后，源机器的批次在目标机器上照常成区、可单独清除。
- `remove_partition(name, delete_words=True)`：先算 present/missing，
  走 `delete_entries`（自带备份+写锁+历史记录），再删 json 条目或 auto 批次的 manifest 文件。
  名称以 `[自动] ` 开头的分区不允许手动创建（保留前缀）。
- `query_entries(..., only_words=...)`：分区过滤在关键词过滤与分页之前生效，
  `total_all` 仍报全库数；导出清单同样只导当前分区。

## 前端

- Treeview `selectmode="extended"`：点一条 → Shift 连选 / Ctrl 加选，工具行有提示文案。
- 新增「分区：」Combobox（全部词条 + 手动 + 自动），选中即按 `only_words` 过滤并重置页码；
  「选中存入分区…」把当前勾选项存进新分区（重名合并，存后保持选中并切到新分区视图）；
  「分区清除」askyesno 确认后删除该分区词条+记录（走 `_run_async`，完成后再刷新）。

## 实测（真实 GUI，临时 APPDATA）

  `partitions.json` 落盘内容正确（8 词、created、machine），下拉框即时出现并切到该分区视图。

## 真机实证：写完词库为什么"没效果"（2026-09-19，F19）

用户实测：OpenIME 写入成功、文件里能查到新词，但打字时不出候选。真机诊断（全程未开 GUI）：

- 词库文件**未被排他锁定**，但 `TextInputHost.exe`（微软输入法宿主）启动时把 UDL 读进内存，
  之后**磁盘改动不可见**；中英文切换不重载（旧提示文案"切一次即生效"是错的，已改）。
- 运行中的输入法学习新词时会**自己回写该文件**（真机 mtime 与词条时间戳证实），
  所以"写完不重载、继续打字"存在旧内存副本覆盖新写入的风险。
- **重载手段实证**：`taskkill /F /IM TextInputHost.exe` 后系统秒级自动拉起新进程，
  新进程读盘，词库改动生效——无需注销、无需重启电脑。探针词「词库生效探针」写入→杀→重启→
  6 秒后仍在盘，未被回写覆盖。

**修复（F19）**：新增 `app_core.reload_ime()`（taskkill 封装：成功/进程不在/真失败/异常四分支，
非 Windows 拒执行）；GUI 管理区加「重载输入法」按钮（确认框说明会闪断）；
CLI 加 `OpenIME reload-ime`；`apply_tokens` 结果文案由"注销重新登录/切换中英文"改为指引一键重载。
回归：test_round5 新增 §4（6 断言，`subprocess.run` 全 mock，**测试绝不真杀进程**），共 28 断言；十套全过。
